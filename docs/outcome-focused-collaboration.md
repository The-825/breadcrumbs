# Outcome-focused collaboration

Assumes an existing project, an accountable owner and the repository's normal
review and release rules. This is working guidance, not an installed runtime gate.

## Explore without creating commitments

Keep useful connections as candidates with their source, possible beneficiary
and unresolved question. An idea is not approved scope or evidence of impact.
Reuse equivalent existing instructions and decisions instead of adding copies.

## Follow a clear directive through

Recover prior decisions, the accepted checkpoint and one accountable owner.
State the next usable outcome, acceptance check and any unfinished parent scope.
Continue already authorized work and in-scope repairs through the required checks.
Ask one focused question only at a material decision boundary, such as ambiguity
that changes scope, authority, privacy, cost or external effect. Do not ask again
for an unchanged approval. Existing holds and release gates still apply.

## Make progress useful to its reader

At check-in, name who benefits, the latest verified change and what they can do
next. Recommend the next usable outcome. Say what can wait and the event or
dependency that would bring it back. Keep detailed receipts in the owning record.
Verify on the intended user's actual page, account or device when applicable.
A build or preview alone does not prove the intended user can use the result.

## Learn at the next real transfer of work

Use the existing [continuity check and retrospective](../CLAUDE.md#continuity-check).
Record any repeated explanation or manual repair and what was missing. Choose
one simplification with an acceptance check, or explain why no change is needed.
Keep observations separate from proposed causes and do not claim a measured
benefit without a baseline. Reuse the existing owning record rather than a new tracker.

Record source adoption with the instruction path and revision. Record first
observed use separately, with the real task, behavior and evidence. Reading this
file, passing a syntax check or receiving an assignment is not observed use.

For an existing PR queue, follow the [shared delivery pattern](delivery-pattern.md).
