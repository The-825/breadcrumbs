# Collaborative intelligence repository landscape, Wave R4

**Status:** public, README-screened inventory of 106 repositories added to the
[landscape](collaborative-intelligence-repository-landscape.md), bringing the
reviewed cohort to 206. These are pinned mechanism observations, not product
scores, runtime tests, or evidence that collaboration improves outcomes.

**Where this wave came from.** The
[public assessment transfer](collaborative-intelligence-repository-collection-log.md#2026-08-29-public-assessment-transfer)
imported 214 repositories that were originally collected for an unrelated
purpose (personal tool and idea scouting), not screened against this ledger's
inclusion rule. D-45 (`planning/DECISIONS.md`) ruled that promoting them
required the same triage the landscape method already applies to any
candidate: public, canonical, contains code or a specification relevant to at
least one `CI-001` through `CI-017` claim, and pinnable to a reproducible
revision. Of the 214, 107 initially passed triage; one (`milvus-io/milvus`)
was then found to duplicate a repository Wave R3 had already screened out as
storage overlap and was moved to excluded for consistency, leaving 106 that
receive the full review below. The other 108, each screened out for a
documented reason, are in the
[collection log](collaborative-intelligence-repository-collection-log.md#wave-r4-2026-08-29)
and do not appear in the machine or human views, the same convention Waves R1
through R3 use.

Stars were observed on 2026-08-29 (each promoted record carries its own
`stars_observed_date`, separate from the 2026-08-27 observation date on the
original 100-repository cohort) and only order discovery within this ledger.
They explain audience size, not quality. One repository
(`evidence-gate/agentgov`) genuinely has 0 stars; that is real, sourced data,
not a missing value.

## What is different about this wave

Unlike Waves R1 through R3, this wave was not popularity- or gap-directed
discovery. It resolved an already-imported, unfiltered list. Two consequences
follow. First, category balance was not a selection goal here the way it was
for R1 through R3; memory-runtime and agent-runtime dominate simply because
that is what the source list happened to contain, not because this wave
targeted those categories. Second, several included repositories are narrow,
single-purpose tools (a destructive-command guard, a PII redaction hook, a
task queue) rather than general platforms. A narrow scope is not a lesser
appraisal; the method records what a repository documents at its own stated
layer, and `O` is used where a dimension sits outside that layer.

## Boundary

Each row records only what was visible in the pinned README at the time of
review. `N` means not observed at that depth, not absent from the full
codebase. A README's own benchmark, comparison table, or reported percentage
is the repository's self-reported claim, carried here as evidence of what the
project documents about itself, not as an independently verified result.
Deterministic checks, fuzz targets, and conformance tests are stronger than a
self-graded claim, but they are not automatically a distinct verifier; same-
model review, role separation, and an evaluation tool do not establish
independent verification without a distinct verifier and evidence path,
consistent with Wave R3.
