# Inbox to briefing

**Status:** public, pattern-only exercise. No inbox integration ships in this kit.

**Assumes:** you have a text editor and the fictional messages below. An AI assistant may draft the table, but you review it. Use authorized access and keep real messages in their owning system.

A tidy summary can hide an unanswered request. Start with the reviewed [working memory card](00-working-memory-card.md). Make a briefing that points back to each source and distinguishes what was said from what you propose.

## Fictional inbox

| Source | Message |
|---|---|
| M1 | "Please send the room layout for Saturday's community workshop by Thursday. I can review it." |
| M2 | "The supply list is in the shared folder. No action needed from me." |
| M3 | "Can someone confirm who will bring the sign-in sheets?" |
| M4 | "I sent the draft agenda to the workshop lead and am waiting for feedback." |
| M5 | "The venue opens at 9 a.m. on Saturday. Keep this for the day-of notes." |

## Your action

Make one briefing table with source, explicit request or fact, owner, due date, status (action, waiting, reference), and proposed next step. Write `not stated` for any owner or date the message does not supply. If you use an assistant, paste only these fictional messages and ask it for the table plus one unsent reply draft to M3.

For M1, the requested item is the room layout and the date is Thursday. The sender offers review, but the message does not assign a sender for the layout. M3 also has no assigned owner or due date. Treat both gaps as questions, not facts.

## Human check

Open M1, M3, and M4 while reviewing the proposed actions. Check that each row still points to its source, no invented deadline or owner appears, and the reply draft makes no promise on someone else's behalf. Save the reviewed table as your briefing. Do not send or archive anything as part of this exercise.
