# Note what matters, then ask what changed

**Status:** public, pattern-only exercise. This page ships as documentation. It does not enable persistent storage, capture messages, or grant an agent access to any account.

**Assumes:** you have a text editor and the fictional messages in the next exercise. For real work, keep the note in an authorized place and agree on who can see it before saving sensitive details.

First principle: keep it simple. When you finish a conversation, note one thing worth remembering and one thing to check next time. When you return, ask what changed. The original message or document still holds the details.

## Fictional note

```text
Topic: Saturday workshop.
Remember: The room layout was requested by Thursday.
Check next time: Who will bring the sign-in sheets? Did the workshop lead reply to the draft agenda?
Where to look: Fictional messages M1, M3, and M4.
```

## Your action

Read the [fictional inbox](01-inbox-to-briefing.md#fictional-inbox), especially M1, M3, and M4. Copy the note into a temporary local file and check it against those messages. Then write your own two-line version: what matters now, and what you want to check when you return. Keep a message reference if it helps you find the original. Do not copy real inbox bodies, transcripts, or personal details into this exercise.

## Human check

Ask another reader what they would check when they return to this topic. If a later message answers the sign-in-sheet question or changes the room-layout request, update the note and point to that message. Do not keep the old wording as if nothing changed. This note helps you resume the work; it does not decide what to do or turn on an automated memory service.

For a larger repository memory system, see the kit's [memory desk](../memory-desk.md) and [copyable memory tools](../../templates/memory-desk/README.md). The [session-state template](../../templates/SESSION_STATE_TEMPLATE.md) helps with longer handoffs. Start with this small note before adding machinery.
