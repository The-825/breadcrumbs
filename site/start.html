Your first useful result

Leave a handoff the next session can use.

A new agent session should find your task, its current state, and the next action without making you repeat the whole conversation. Begin with a single task and a file you control.

Ships: editable Markdown templates under the MIT license. Assumes: a text editor and a repository you own. No install, account, or API key required for this starter. Your agent must be told to read the file; copying it does not create automatic memory.

Start with the handoff. Add structure when you need it.

1. Preserve the next step

Session state

Open the file and copy the Markdown block under "The template" into a local file named SESSION_STATE.md. Fill in the current task, evidence of completed work, unfinished work, and the next action. Keep this copy in your own repository.

Open the handoff template

2. Make boundaries explicit

Rules file

If sessions keep missing your conventions, adapt the rules template to your project. Use the filename your agent reads, such as AGENTS.md or CLAUDE.md. Link it to your session-state file.

Open the rules template

3. Keep decisions findable

Decision ledger

If a settled choice keeps getting reopened, record the ruling, why it was made, and its source. Start with one real decision instead of importing an entire chat history.

Open the decision template

Check the result in a fresh session.

Ask your agent to read the rules and session-state files, then use this prompt:

Before changing anything, tell me the current task, what evidence supports its status, what remains uncertain, and the next action. Cite the file and section for each answer. If the files do not answer something, say so.

Your first result is a checkable handoff, not a memory score. Compare the reply with the files yourself. If the agent guesses or cannot find the next step, make that part of the handoff explicit and try again. One successful trial does not establish reliability.
