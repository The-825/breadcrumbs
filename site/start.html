Your first useful result

Leave a handoff the next session can use.

A new agent session should find your task, its current state, and the next action without making you repeat the whole conversation. Begin with a single task and a file you control.

Ships: editable Markdown templates under the MIT license. Assumes: a text editor and a repository you own. No install, account, or API key required for this starter. Your agent must be told to read the file; copying it does not create automatic memory.

1. Copy one file into your project.

Open the handoff template

On GitHub, find "The template" and copy the contents of its Markdown code block. Paste them into a text file named SESSION_STATE.md in the top-level folder of your own project, beside its README. Do not include the surrounding triple-backtick markers.

If that file already exists, update its relevant sections instead of replacing it. No command or installation is needed.

2. Fill in one current task.

Replace the placeholders with the task you want to resume. Record what is complete, the file or test that supports that claim, what is unfinished, and the next action. Use "unknown" or "not applicable" where you cannot provide a value.

For example, a fictional task could say: "The help-page draft is in docs/help.md. It has not been reviewed. Next action: check the setup instructions against the application." A saved draft is evidence of writing, not evidence of review or deployment.

Save the file. Your output from this step is a current, local handoff you can inspect yourself.

3. Ask a fresh session to read it.

Open a new session in your coding agent with this project folder selected. Paste the prompt below. If the agent cannot access local files, use a fictional handoff for this exercise or attach only information approved for that service.

Read SESSION_STATE.md in this project's top-level folder and any existing project rules. Before changing anything, tell me the current task, what evidence supports its status, what remains uncertain, and the next action. Cite the file and section for each answer. If the files do not answer something or you cannot read them, say so.

4. Check the answer before continuing.

Ready to continue

The task and next action match your file. Completed work has a real evidence reference. Unknowns stay unknown. Confirm the next action before the agent changes anything.

Fix the handoff

The agent guesses, misses a blocker, or calls unfinished work complete. Correct the relevant section, save it, and repeat the check in a fresh session.

Fix file access

The agent cannot read the file. Check the selected project folder, filename, and access settings, then retry. Do not treat a plausible answer as proof it read your handoff.

When you finish the task or change direction, update the handoff again. One successful trial shows this handoff worked for that session; it does not establish general reliability.

Add these only when you need them.
