The method in plain words

Cue-placement memory.

Keep short notes in files you own. Each note points to a decision, a source or the current next step, instead of retelling the whole story. A new session reads the note and follows the pointers.

The tool has to be told to read the notes. Writing a file does not create automatic memory, and a plausible answer is not proof the file was read.

An example: where we left off

Task: Update the volunteer sign-up guide.
Status: Draft is in docs/signup-guide.md. Nobody has reviewed it.
Decision: Use the shared form, not email. Reason and source: docs/decisions.md, entry 3.
Next step: Check steps 1 to 4 against the live form, then ask a second person to review.

Check it in a fresh session

  1. Open a new session with this project folder selected.
  2. Ask it to read the note and tell you the task, the evidence for its status, what is uncertain and the next step, citing the file and section for each.
  3. Compare the answer with your note. If it guesses or calls unfinished work done, fix the note and ask again.
